# 只读检查 Mac 变慢

先按 execution skill 确认命令实际在用户的 Mac 上运行。只检查意味着不清内存、不关闭程序、不改设置，也不运行压力测试。`memory_pressure` 是施加/模拟内存压力的工具；不要把它或未经核实的参数当成只读查询。

## 内存

先取少量有界观察：`sysctl hw.memsize vm.swapusage`、`vm_stat -c 3 1`，必要时用 `df -h /System/Volumes/Data` 查看存储空间。命令结果保留原单位，页面大小取实际输出。`vm_stat` 第一行是总计，后续间隔行是变化量；开机以来累计换页不能证明此刻正在大量换页。短采样没有变化也不能排除间歇性问题。

macOS 会利用缓存、压缩和交换。空闲内存少不等于内存不足，压缩量没有通用的“正常 1 GB”阈值；已用交换量不是当前交换速率，也不能用 used/total 百分比宣称交换空间快耗尽。Apple 的内存压力同时考虑空闲内存、交换速率、联动内存及文件缓存。缺少当前压力或持续换页证据时，结论应是“尚不能确认内存不足”；低空闲、旧交换占用和短采样近零增量不足以说“内存偏紧，很可能是变慢原因”。不要猜测未验证版本的内核字段或数字枚举。

如已有可靠可读的“活动监视器 → 内存”观察，绿色表示使用高效，黄色表示可能需要更多内存，红色表示需要更多内存。颜色也不能单独证明此次变慢的原因；结合同时段症状判断。能用实际可用的只读观察工具就先查，否则说明当前未知，不默认让用户打开活动监视器，也不承诺看颜色即可确定原因。负载均值除以核心数不是 CPU 使用率，不能据此断言超载。不能读取进程列表时，不猜哪个应用占用最多，也不默认要求用户改系统权限。

回复先给可支持的结论，再给一两项关键观察。例如“暂时还不能确定是内存不足。系统在使用压缩和交换，但还需要当前内存压力才能判断。”若已有可靠压力和近期变化证据，再说明可能相关的瓶颈；不要把相关性说成唯一原因，也不把整段命令输出贴给用户。

依据：[Apple 内存使用说明](https://support.apple.com/guide/activity-monitor/view-memory-usage-actmntr1004/mac)、[Apple 内存压力说明](https://support.apple.com/en-lamr/guide/activity-monitor/actmntr34865/10.14/mac/15.0)，以及执行设备的 `man vm_stat`、`man memory_pressure`。后两者说明命令语义，不提供通用性能阈值。
