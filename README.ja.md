# Athena

[English](README.md) · [简体中文](README.zh-CN.md) · 日本語

Athena は、会話から使い始めるパーソナルアシスタントです。やりたいことを伝えると、進捗、結果、必要な操作がその都度表示されます。普段の利用に、モデル、API キー、Agent フレームワークの知識は必要ありません。

現在は Python 3.14T、SQLite、TypeScript、React を使った **macOS とホスト型 Web の限定プレビュー**です。能力を段階的に拡張できる汎用アシスタントであり、コーディング専用の UI ではありません。[製品方針](docs/product.md)（中国語）では、実装済みの機能と検証中の構想を区別しています。

現在のプレビューには、独立したアカウント/モデルゲートウェイ、クレジットなしでの登録、監査可能な米ドル建てテストクレジット、Apple Silicon 向けの自己完結型 macOS テストパッケージも含まれます。ゲートウェイは実際のプロバイダーストリームと精算の確認に合格しました。認証付きの[ウェブプレビュー](https://chat.athena.featherhk.com/)と [Mac ダウンロードページ](https://app.athena.featherhk.com/)は Tencent Cloud 上で HTTPS 公開済みです。DMG はアドホック署名で、公証されていません。音声のターン制御、中断、プロバイダーアダプターは実装済みですが、実際の音声経路とマイク通話はまだ検証されていません。[リリース準備状況](docs/requirements-status.md)、[クラウド運用](docs/cloud-deployment.md)、[デスクトップ配布](docs/distribution.md)、[音声](docs/voice.md)を参照してください。

## 実装済みの機能

- 表示名とアバターを設定できるユーザーアカウント。パスワード変更は固定の専用フォームで行い、パスワードをモデルのメッセージやツールに渡しません。モデルの認証情報はサーバー側で管理します。
- UI はアラビア語、英語、スペイン語、フランス語、日本語、韓国語、ポルトガル語、簡体字中国語、繁体字中国語の 9 言語に対応。ブラウザー設定を自動判定し、未対応の場合は英語を使用します。国旗を使わず各言語の名称を BCP 47 タグ順に表示し、アラビア語は右から左のレイアウトに対応します。UI の言語、フォント、配色、アニメーション軽減は、返答の好みとは別に保存します。
- 安全な Markdown 表示、プロバイダーが実際に返した reasoning の個別折りたたみ、思考・返答・実行の状態表示に対応したストリーミング会話。永続イベントにより再接続後も更新を取得でき、ブラウザーを閉じてもタスクは停止しません。
- 別の会話に移動しても、バックグラウンドの進捗、回答待ちの質問、未読の結果を確認でき、ファイルのプレビュー内からもアクセスできます。更新によって会話が自動で切り替わることはなく、Athena も同じ `runtime` で状況を確認・管理できます。[タスクの継続性](docs/task-continuity.md)を参照してください。
- 会話に紐づく添付ファイルと生成ファイル。自分のファイルをダウンロードし、Markdown、隔離された HTML、画像、表示範囲を制限した XLSX のセルとキャッシュ値をプレビューできます。
- macOS の管理ブラウザーでは、同じ runtime ツールで独立した永続ログイン状態、会話ごとのタブ、ページ観察、フォーム、ダウンロード、スクリーンショットを扱います。応答が失われても操作を自動再送しません。[ブラウザー実行](docs/browser-execution.md)に検証と制限を記載しています。
- メッセージのキュー、割り込み、停止、会話の分岐。分岐は固定された履歴境界を引き継ぎ、バックグラウンドタスクは一時停止状態で複製します。
- `runtime` で独立したサブタスクを並行実行できます。コンテキストとファイルを分離し、待機・再開、結果参照、分岐単位の停止を永続化します。質問と生成ファイルは主会話に戻り、費用にはサブタスク分も含まれます。会話の分岐は過去の記録を保持し、サブタスクを再実行しません。[分担の仕組み](docs/delegation.md)を参照してください。
- OpenAI 形式の基本ツールは `exec`、`update_frontend`、`runtime` の 3 つ。runtime は小さな `{op, args}` 形式を使います。Skill は `SKILL.md` のメタデータを持つディレクトリパッケージで、スクリプト、参考資料、テンプレートなどを含められます。本文とリソースは必要なときに読み込みます。
- ツール、コンポーネント、スキル、ポリシー提供者をソースリポジトリ外でバージョン管理します。過去の登録を復元すると新しいバージョンが作成されます。フロントエンド拡張はインライン、ワークスペース、サイドバー、固定、オーバーレイ、全画面、プレゼンスの各表示面に対応し、ライブ更新と描画レシートを備えます。入力・停止・ナビゲーション・リセットは固定シェルに残ります。
- 接続済みのポリシーフックは、コンテキスト圧縮、記憶の取得、コマンド準備の 3 種類です。プラグインは制限付きサブプロセスで実行し、失敗・タイムアウト・無効な出力では既定動作に戻ります。サービス ID は自由に登録できますが、利用側が未接続の登録は待機中と表示され、動作を変更しません。
- タイマー、定期タスク、スクリプトで表す条件付きタスク。条件確認では LLM を呼び出さず、成立時に元の会話へ処理を追加します。
- ユーザー・プロジェクト・会話単位の明示的な記憶、復元可能なツール出力の切り詰め、使用量・キャッシュ・推定費用・コンテキストの実行時確認。指定した推定トークン量を目標に圧縮し、元のメッセージ、reasoning、ツール呼び出しの対応関係を保持します。usage やモデル上限が不明なら、不明のまま扱います。
- 任意の開発者ウィンドウと、運用者が登録する Chat Completions モデルプロファイル。Athena の製品としての識別を保ち、次のリクエストからプロファイルを切り替えて監査可能なコンテキストバージョンを作成します。Reset は処理を停止し、既定設定へ戻し、拡張を無効化してタスクを一時停止します。会話、ファイル、記憶、過去のバージョンは保持します。

[受け入れ基準](docs/acceptance.md)で観察可能な結果を、[プラグイン設計](docs/plugin-architecture.md)で現在の実装範囲とサービスホストへの計画を確認できます。

## ローカルで起動する

Athena は `runtime` で同じアカウントの会話を検索・閲覧し、会話の作成・改名、アイドル状態の会話の分岐を行えます。完了した実行は現在のモデルコンテキストから除外し、後で復元できます。元の会話はそのまま保持されます。ブラウザーのナビゲーションなどシェル操作には、対象クライアントの指定、範囲を限定した状態観察、永続化された要求と確認応答を使います。プレビュー表示とファイルの準備完了は区別します。セッション ID を返すだけではナビゲーションは行われません。[フロントエンド状態](docs/frontend-state.md)を参照してください。[自然言語によるコマンド検証](docs/command-acceptance.md)も参照してください。

ソース版の既定はローカル BYOK です。Feather アカウントなしで、ご自身のモデルに接続できます。ホスト型プレビューは引き続きクレジット付きの有効なアカウントを使用し、登録だけではモデルを利用できません。

必要環境：macOS、`uv >= 0.9`、Node.js `>= 24`、npm。管理ブラウザーには Google Chrome または Chromium のインストールも必要です。

```sh
uv python install 3.14t
uv sync --locked
npm ci
uv run --directory backend python -m athena.doctor
npm run build
npm start
```

[Athena](http://127.0.0.1:4317) を開きます。新規インストールでは専用のローカル ID が作成され、「モデル接続」が開きます。DeepSeek、ローカルモデル、または OpenAI 互換 Chat Completions API を選び、モデル ID、ベース URL、ご自身のキーを入力します。保存時に有料の接続テストは行いません。次のメッセージから設定を使用します。

ローカルモデルには `http://127.0.0.1:11434/v1` などのループバック URL をキーなしで使えますが、モデルサーバーは別途起動しておく必要があります。リモート API は HTTPS とキーが必要です。アドレス変更時に以前のキーを別の接続先へ転送することはありません。モデル変更は不変のプロファイルと監査可能なコンテキスト境界を作成します。実行中のタスクは終了または停止してから変更してください。このフォームはネイティブの Anthropic Messages や Responses API には対応しません。

アカウント不要の設定は、ループバックで待ち受け、`ATHENA_CLOUD_URL` と `ATHENA_PUBLIC_ORIGIN` がない場合に限ります。既存のアカウントや会話は従来のログイン・登録方法を保持し、自動統合されません。個別に試すには `ATHENA_DATA_DIR` をリポジトリ外の新しいディレクトリに設定してください。公開リスナーでは自動ログインを有効にしません。`--cloud-url` を指定せずに作った Mac パッケージも BYOK を使用し、ホスト型パッケージは従来の認証を使います。

既存アカウントの環境や運用向けには、別のターミナルで非表示入力による設定も利用できます。

```sh
uv run --directory backend python -m athena.admin provider-key
uv run --directory backend python -m athena.admin status
```

内容を表示せず、ローカルファイルから読み込むこともできます。

```sh
uv run --directory backend python -m athena.admin provider-key --file /path/to/private/key.txt
```

既定のプロファイルは、DeepSeek 公式 API の `deepseek-flash`（DeepSeek V4.1 Flash）を使用します。サーバー側の環境変数 `DEEPSEEK_API_KEY` は元の `default` プロファイルの保存済みキーより優先されます。BYOK フォームで作成したプロファイルは、それぞれの保存済みキーを使用します。保存した認証情報はローカルデータベースに置かれ、クライアントには返されません。システムキーチェーンとの連携は未実装です。認証情報の変更に再起動は不要です。

フロントエンド開発には `npm run dev` を使います。Vite はポート 5173 で起動し、API リクエストをポート 4317 のバックエンドへ転送します。

起動には free-threaded Python 3.14 が必要で、依存ライブラリが GIL を有効にしていないことも確認します。現在、プロジェクト内の uv 設定で USTC PyPI ミラーを使用しています。グローバルなパッケージマネージャー設定は変更しません。

## 別のモデルを設定する

バックエンドは DeepSeek に固定されていません。運用者が変更不可のモデルプロファイルを登録し、Agent はその中から選択します。任意の接続先や認証情報を Agent 自身が指定することはできません。

```sh
uv run --directory backend python -m athena.admin register-model \
  --id second-model \
  --provider 'Provider name' \
  --model 'api-model-id' \
  --base-model 'Underlying model name' \
  --api-base 'https://provider.example/v1'

uv run --directory backend python -m athena.admin provider-key --profile second-model
```

例の値はプロバイダーの公式設定に置き換えてください。`register-model --help` で、指示ロール、出力トークンのパラメーター、reasoning の保持、生成設定、コンテキスト上限のオプションを確認できます。定義を変更する場合は新しいプロファイル ID を使い、実行中のリクエストと監査記録の意味を保ちます。

現在のアダプターはストリーミング **Chat Completions** API 向けです。ネイティブの Responses、Anthropic Messages などには別のアダプターが必要です。プロトコル互換性は、すべてのプロバイダーやモデルで検証済みという意味ではありません。モデル切り替えは会話記録を保持したまま次のリクエストから適用し、プロンプトキャッシュの区切りとして扱います。実際のキャッシュ動作はプロバイダーに依存します。

## ランタイムとデータ

同じ会話内では順番に実行し、別の会話は並行して処理できます。イベントループの状態には単一の所有者を定めています。SQLite 接続は専用ワーカースレッドで使用し、WAL とトランザクションで状態を更新します。同期処理を GIL に依存させていません。

実行データはリポジトリ外に保存します。

| プラットフォーム | 既定のデータディレクトリ |
| --- | --- |
| macOS | `~/Library/Application Support/Athena` |
| Windows | `%LOCALAPPDATA%/Athena` |
| Linux | `$XDG_DATA_HOME/athena`、または `~/.local/share/athena` |

`ATHENA_DATA_DIR` で変更できますが、ソースリポジトリ外の場所を指定する必要があります。このディレクトリには `athena.sqlite3`、完全な出力、ユーザーファイル、拡張機能の各バージョン、非公開のブラウザープロファイル領域が含まれます。バックアップはサービスを停止してから、ディレクトリ全体を保存してください。[イベントの可逆圧縮](docs/event-storage.md)では作業前にデータベースをバックアップします。定期バックアップと暗号化は未実装です。

メッセージ、モデルリクエスト、ツール結果、条件確認、起動トリガー、モデル切り替え、切り詰め記録を監査できます。イベントは配信前に保存します。バックエンド再起動時には未完了の処理を中断状態にし、副作用の可能性がある操作を自動再実行しません。クライアントの切断とバックエンドのクラッシュでは、復旧の保証が異なります。

ローカルのバックグラウンドタスクには、サービスとコンピューターの稼働が必要です。ホスト型のタスクはサーバーの実行ノードを使います。再開時には未実行の周期をまとめて処理します。条件確認は 1 回最大 30 秒、実行間隔は最低 60 秒です。メール送信などの外部操作には、実行側での冪等性の確保や結果の確認が必要です。

`.gitignore`、リポジトリチェック、Git フック、CI により、実行データや一般的な形式の認証情報の誤コミットを防ぎます。実際の会話、Cookie、スクリーンショット、データベース、私的なファイル、モデルリクエスト記録をテストデータに含めないでください。JSON は通常のソース・設定形式として使用できます。

## 現在の制約

macOS のコマンド実行器は Seatbelt を使い、アプリケーションソースへの書き込みを禁止し、Athena の実行データへのアクセスを制限します。登録したコードはユーザーファイル領域に保存します。ただし、悪意のあるテナントを隔離する完全なサンドボックスではありません。ローカルユーザーの権限でアクセス可能な他のホスト資源は残っています。ホスト型 Linux のコマンドと管理 Chromium は、アカウント別の[コンテナー実行アダプター](docs/linux-execution.md)を使います。保護アダプターのないプラットフォームではコマンド実行を無効にします。ローカルランタイムはループバックで待ち受けます。ホスト型デプロイでは独立したゲートウェイと明示的な HTTPS オリジンを使用します。汎用の公開実行サンドボックスではありません。

現在の Engine と Store は、Agent のループと永続化を直接実装しています。サービスホストの背後で交換できる提供者にはまだなっていません。既存のポリシーフックだけで、モデル通信、スケジューラー、認証、フロントエンド全体を交換できるわけではありません。利用側のないサービス ID を登録しても連携は有効になりません。アプリケーション本体の更新には、引き続き制御された再起動が必要です。

今後実装または検証が必要な項目：ブラウザーの画像入力、独自のファイル選択 UI とポップアップ処理、デスクトップ操作、OS 通知、本番向け実行分離の評価、署名・公証済み配布、iOS 実機検証と Android/Windows クライアント、実際の音声通話、幅広いタスク品質評価。中央アカウントと予約/精算台帳はありますが、決済受付、アカウント復旧、本番精算は対象外です。XLSX プレビューは範囲を制限した読み取り機能であり、表計算エンジンではありません。プロトタイプの方針として、操作ごとの承認フローは設けていません。

## 検証

```sh
npm run check
node scripts/check-repository.mjs --staged
```

自動テストはモデル応答のモックを使い、API 料金は発生しません。アカウントとファイルの所有権、設定と返答の好みの区別、ストリーミングと割り込み、復旧と分岐、登録バージョンと復元、スキルリソース、ポリシーのフォールバック、使用量と圧縮、言語判定、リポジトリのデータ管理について、観察可能な状態変化を確認します。同じコマンドで TypeScript の検査と本番ビルドも実行します。Safari とアプリ内ブラウザーでも、会話の表示、追加情報の回答後の再開、コンポーネントの削除、テーマ変更、狭い画面を確認しました。新規のローカルモデル設定、実際の HTTP モックストリーム、再読み込み後の保存状態もアプリ内ブラウザーで確認しました。[デザイン方針](docs/design-language.md)と[検証記録](docs/acceptance.md)を参照してください。ブラウザーによるブロックはオリジンと検証回ごとに記録し、Chrome 全体の対応状況や管理ブラウザー実行機能の評価とは区別します。

任意の実モデル評価は、一時アカウントと一時データベースで実行し、既存の利用者の会話は使いません。

```sh
uv run --directory backend python ../scripts/evaluate_requirements.py --key-file /path/to/operator-key
```

この確認は API 料金が発生するため CI に含めません。判定と使用量、および失敗時の短い合成テスト診断を出力します。認証情報やプロバイダーへのリクエスト記録は出力せず、終了後に一時データを削除します。`--case NAME` を繰り返して個別のケースを選択できます。実際の DeepSeek で、UI 言語、外観、継続的な返答の好み、表示名、新しいツールの登録と実行、使用量とコンテキストの確認、他の会話の閲覧、復元可能な圧縮、完了ターンの除外を確認しました。圧縮の成功は元の内容を保った投影の短縮を意味し、正確な token 数の達成を保証しません。幅広いタスクの成功率、ブラウザー操作、他のプロバイダーまで検証済みという意味ではありません。
