## User-visible behavior

When a send response is lost, Athena retains the original send identity and
offers status lookup or an explicit retry. Reloading or returning to a chat
only checks the receipt; it does not silently resubmit. A late receipt cannot
erase a newer draft. An intentional new message with the same words remains a
new task. Recovery records are scoped to the account and conversation.

Stop now has its own durable identity. An unconfirmed Stop keeps new work from
overtaking a possibly delayed cancellation. Retrying that Stop uses its original
identity, so a late duplicate cannot cancel a later task. One contextual warning
provides status and retry controls; it does not add permanent composer buttons.
The [receipt contract](../submission-intents.md) describes the protocol and its
limits.

Memory recall can include older entries that match the current task, together
with bounded recent entries from visible scopes. Corrections and withdrawals
are resolved before the first provider request; historical requests and frozen
prefixes remain unchanged. This uses bounded lexical matching, not semantic
search or automatic contradiction resolution. See the
[memory review](../reviews/2026-10-05-memory-recall.md).
