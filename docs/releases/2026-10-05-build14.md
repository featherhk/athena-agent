## User-visible changes

An XLSX preview now retains typed cell values and the workbook's saved formula
results. Supported currency, percentage, decimal and date/time formats preserve
their value meaning. Dates are normalized instead of imitating every Excel
display convention. Unsupported or ambiguous formats fall back to the stored
value with an explanation; fractional times that would round across midnight
do not silently become a different calendar date.

Formula cells distinguish a saved result, a missing cached result and an
explicitly saved empty result. A numeric zero hidden by the workbook's format
is identified separately. Expandable cell details expose the stored value,
formula and number format, with a cell-address label. The preview does not run
formulas or infer that a missing cache means the formula evaluates to empty.
Notes explain that saved results may be stale when the workbook requests
recalculation or uses manual calculation.

The table stays in the conversation, supports worksheet switching and retains
the original download. Wide sheets scroll inside the preview. Numeric and
formula cells align consistently; bidirectional isolation preserves values and
formulas in Arabic. Worksheet rendering is memoized so unrelated typing and
streaming updates do not repeatedly traverse an unchanged table. The
[implementation review](../reviews/2026-10-05-spreadsheet-preview.md) records the
supported subset and fallback behavior.

## Hosted task acceptance: partial, with explicit remaining issues

A synthetic quotation workbook was uploaded to an owned test conversation on
the hosted service. Its preview returned the expected displays and formula
states, and downloading the original preserved its bytes. One explicit model
task checked the arithmetic and produced a registered output copy with exactly
the same bytes. The material and labor subtotal was 1960; adding 8% tax yielded
2116.8. This proves the requested check-and-copy path, not an edited or
recalculated workbook.

The actual browser displayed the output inline. Opening cell D6 showed stored
value `2116.8`, formula `D5*(1+B4)` and the currency number format, while the
displayed value remained `¥2,116.80`. The hosted API receipt, downloaded bytes
and browser screenshot support that narrower success.

**The full user experience did not pass without qualification.** The model's
prose called a formula with no cached result an empty result. Missing cached
data does not establish an empty calculation, and the native preview correctly
kept these states separate. The model also created a redundant custom result
card repeating the reply and existing native preview. These remain follow-up
issues for evidence-grounded file explanations and avoiding duplicate
presentation. A completed run and correct output bytes do not excuse either
problem; this release does not claim flawless spreadsheet assistance.

The task took **30.076 seconds**, with **11 model requests** and **12 tool
calls**. All 11 requests settled once, with matching account debits totaling
**$0.008376** under Athena's configured tariff; this is not a provider invoice.
Across requests, 63,232 of 72,109 input tokens were cached (**87.69%**). There
was one message admission and no exact-argument replay. Two interface calls
returned errors. The extra custom-component path is a concrete efficiency
follow-up; a high cache hit rate alone does not establish a good experience.
