# Athena 产品约束与验证路线

更新时间：2026-10-05。本文区分产品目标、待验证假设、已有实现；它不是对现有代码成熟度的承诺。

当前实施优先级见 [从能力原型到实用产品](reviews/2026-10-05-usable-product.md)：先验证文件交付与修改、带证据的查询、持续跟进与送达三类日常任务，优先修复重复提交、用户时区、文件恢复和记忆召回缺口。跨端接续、浏览器接管及真实语音验收服务于这些流程；自定义界面继续保留，避免它占据主要产品投入。

## 产品是什么

Athena 是一个可长期托付事情、可逐渐定制的个人助手。默认体验是给一个联系人发消息，而不是配置 Agent、选择模型或启动开发环境。用户知道自己要办什么就足够，不要求他知道如何办。

“下限低、上限高”具体落实为同一套能力的渐进暴露：普通用户直接说话；有重复需求的人把成功做法留下来；专业用户能查看执行、组合能力、写扩展、版本化和分享。不能要求所有人先学会专业模式，也不能为简单界面阉割底层能力。

衡量入口是否够简单，不使用年龄或职业作能力判断。邀请缺乏技术经验的真实用户，在不讲解、不提示术语的情况下完成任务。看他们是否能开始、理解状态、认出结果、纠正错误，而不是只问界面是否好看。

## 应当争取的优势

1. **让用户少操心的完成率。** 一句自然需求到可验收结果，尽量减少澄清、接管、重试和需要理解的新概念。不是隐藏失败，而是系统先排查、保留进度、给出下一步。
2. **办成一次后，之后更省心。** 例如“整理这批票据”成功后，用户说“以后都这样整理”，就能留下可复用的小工具、输入约束、验证规则和触发条件。专业用户可以编辑底层实现，普通用户只使用结果。技能分享本身不是创新，真正要验证的是从一次成功到可靠复用是否足够容易。
3. **定制不会把助手弄坏。** 内核不可被 Agent 修改；扩展有版本、隔离、停用和恢复入口。Reset 保留数据。应用恢复与外部行为撤销必须分开：恢复界面不能声称撤回已经发出的消息。
4. **按办成一件事优化成本。** 关注缓存、无模型条件检查、复用已验证程序和合适的模型路由，但最终比较的是被用户认可的成功任务成本。便宜模型若造成更多失败和返工，并不更便宜。

这些目前是可验证假设，不是已建立的护城河。更可能形成长期价值的是用户许可下积累的偏好、经验证的工作方式、可靠的执行与恢复记录，以及优质扩展的供给；不能依赖囤积敏感数据。

## 需要验证的创新方向

**把成功的任务逐渐变成稳定能力。** 每次成功不是只留下聊天记录，而是可选择沉淀成一个带输入、输出、验证、版本和成本边界的能力包。比如费用整理包包含识别步骤、分类规则、账目校验和适合普通人的编辑卡片。下一次优先复用稳定程序，只让模型处理新的判断。对专业用户开放代码，对普通用户开放自然语言调整。

**把长程任务表示为承诺与证据。** “材料到货就提醒我安排师傅”包含条件、检查方式、待执行动作、停止条件、上次证据和负责人。系统空闲时不空转推理，条件满足后回到原来的事情。用户看到“在等什么”“上次何时确认”“完成了什么”，不需要理解 cron、worker 或 webhook。

**让结果自带可检查的依据。** 用户不需要看完整工具轨迹，但可以点开票据来源、前后差异、计算依据和生成文件。评估成功不能只靠模型自报完成。先从可机械验证的任务开始做完整闭环。

这些方向的组合有产品价值，但不能在没有检索和实测的情况下宣称首创。

## 账户、模型、额度的边界

用户注册/登录 → Athena 判断可用额度 → 平台选择模型并执行 → 给出结果与清楚的余额变化。API key、provider base URL、模型选择、重试参数都属于运营和基础设施。客户端及安装包不能包含平台供应商密钥，用户也不负责供应商额度或鉴权故障。

开发者模式是可选的可观测性窗口：展示实际 API usage、缓存命中率、请求状态及明确标注的估算成本。它不是普通用户的必经流程，也不是账单。

正式计费至少需要：独立的账户余额账本；幂等的预留、结算、释放记录；每请求/每任务成本边界；中断和 usage 缺失时的待核对状态；平台故障的扣费规则；充值回调验签、去重与对账。不能直接把浮窗里的估算费用当成对用户的扣款，更不能用客户端数字决定余额。商业价格与退款规则尚未确定，当前没有真实收费。

托管预览已把账户、模型网关与测试额度账本放在服务端，实现请求预留、结算和释放；新账户默认无额度，不开放充值。云端配置的客户端通过中央服务鉴权，不包含平台模型密钥。本机独立开发模式仍可通过服务端环境或运维命令配置密钥。系统通知、设备凭证生命周期与生产级对账仍需完善。

## 架构约束

- **稳定内核**：认证、账本、运行调度、持久化、停止、Reset、扩展协议由应用发布流程更新。
- **用户文件区**：生成文件、前端组件、后端工具代码和版本；Agent 只能经登记使用扩展，不能自行修改应用代码。
- **独立执行节点**：本机动作在用户自己的节点，云任务在独立租户环境；HTTP 的 owner_id 过滤不是完整 OS 隔离。
- **协议稳定、实现可替换**：默认 CLI 是实现偏好，任务成功率与正确性优先。可靠接口更适合时，不为工具数量好看而强行使用脆弱的屏幕操作。
- **失败是产品路径**：网络断开、登录态失效、电脑休眠、额度不足、重复回调、生成中断、扩展崩溃都应有明确状态与恢复规则。
- **可用性不靠模型自报**：验证必须由实际接口、文件、事件和回归任务证明。

## 验收方法

首轮建立真实任务集，而不是先宣称“任何事都能做”：文件整理与查找、信息核对、简单账目、条件提醒、把重复步骤做成小工具。用户群体可以广泛，首轮质量验证必须具体。

北极星指标：每个活跃用户每周认可、且不需要人工代办完成的事项数。并行观察首次任务完成率、主动接管次数、失败恢复率、重复任务复用率、错误外部动作数、成功任务成本、首条有用反馈时延和提醒准确率。按非技术用户与专业用户分别统计，不能只用熟悉 Agent 的工程师验收。

候选内测门槛（目标，不是当前结果）：20 位不同技术背景的用户，在不提供操作教学的情况下完成预设的三项真实任务；核心任务集成功率达到 90%；不中断数据的 Reset 和会话恢复回归必须全过；账务重复结算及跨账号数据访问为零。实际任务集和阈值需要根据首次测试调整，不能用容易的样例刷指标。

## 当前交付与下一步

当前交付：聊天入口和状态标记、中央账户与测试额度网关、账户会话过滤、服务端统一调用模型、开发者 usage 窗口、可恢复裁剪、脚本条件触发、扩展登记与源码写保护、保留数据的 Reset。托管 Linux 命令和受管浏览器已接入隔离执行适配器；前端语义观察、定向会话导航与预览状态可通过统一工具读取并核验。自动测试覆盖关键数据库与协议边界。真实 DeepSeek API 与隔离环境中的注册、发送、回复链路已经验证；这不代表广泛任务成功率。现已接入九种界面语言、系统语言匹配、手动选择、英语回退及阿拉伯语 RTL。

尚未达到消费级发布标准：第三方登录与账户恢复、支付和生产级对账、公证签名与干净机器安装、远程交互式浏览器登录、操作系统通知、真机移动端验收、恶意多租户隔离评估、任务成功率评测和更广泛的真实任务联调仍未完成。Apple Silicon 测试 DMG 已发布但仅为 ad-hoc 签名；iOS 宿主已有构建结果，不能据此宣传为完成真机分发。中央账户与测试额度账本已有实现，不等于完整商用账号和收费体系。

优先级以 2026-10-05 路线为准。语音交互与适配器已有实现，真实音频通道及成本已有具名发布记录；完整麦克风通话、嘈杂环境和真机交互仍需验收。对不习惯输入的用户，语音是实际任务入口，需要按连续通话体验评估，不能只验证接口返回音频。


## 为模型可靠工作提供什么

这里的“模型需要”指运行所需的信息与控制条件，不是把模型拟人化为有主观居住需求的个体。原则是奥卡姆剃刀：能由现有运行记录和接口表达的事实，不再增加一套平行状态。

- **可信的当前状态**：`runtime state` 从数据库读取运行、后台任务、模型与裁剪记录。时间和动态状态放在工具结果，不每轮改写前缀。模型不需要靠猜测判断自己是否已经执行过某个步骤。
- **证据能够找回**：工具结果裁剪只改变发送给模型的投影，完整原文仍可恢复。没有证据时保留“未知”，不把半截流或中断当成执行成功。
- **停止和恢复含义明确**：停止会终止当前命令进程组并记录中断；服务重启不重放可能产生外部副作用的操作。恢复界面、继续任务、撤销外部行为是不同操作。
- **能力边界明确**：当前能调用哪些工具、哪些模型，来自注册表。没有配置的能力不能只靠 prompt 假装存在；扩展有版本、来源和停用机制。
- **身份稳定、模型可替换**：Athena 是产品身份；system 仅补充配置的基模名称；供应商与 API 模型标识通过运行状态和请求记录查询。模型切换在请求边界生效、递增上下文版本并审计。同一配置期间不逐轮改写身份，切换不会重放工具动作。只声明配置来源，不声称通过 API 证明了远端权重身份。
- **按需获取规则**：三种核心工具、短描述和少量 skill 元数据构成入口。完整操作约定按需读取。先把信息说准，再考虑说多。

已有实现支持这些基础机制；尚未实现自动能力评测、跨供应商原生协议适配、模型质量路由或自动验证任意外部动作。默认仍使用 DeepSeek，其他 Chat Completions 配置由运营端登记，只有已配置的模型能被选择。开发者浮窗区分 API 返回的模型字段、服务配置、实际 usage 与价格估算。

## 多语言与视觉表达

语言以 BCP 47 标签作为稳定排序键：ar、en、es、fr、ja、ko、pt、zh-Hans、zh-Hant。该排序是产品约定，不声称国际标准规定了语言的优先级。初次按浏览器／系统语言偏好依次匹配，繁简中文识别脚本和地区；没有受支持的偏好则用英语。用户能选择原生名称或跟随系统，界面不用旗帜。

界面文字、错误码对应提示、日期、数字及阅读方向属于同一套本地化体验。用户内容不被自动翻译，混合语言消息使用自动文字方向。界面偏好已有账户级服务端持久化和浏览器缓存；这不代表 Mac 本机会话与云端会话、文件已经同步。

Athena 的视觉标记使用开放轮廓、半透明折叠和留白表达存在感；空闲、思考、执行和停止有不同运动。状态也有文字／无障碍标签，不能要求用户理解抽象动效才知道发生了什么。系统和手动减少动效均受支持。Safari 和应用内浏览器已用于视觉及交互验收；生成组件与新发布版本仍需分别检查，不能由一次验收推断所有布局可用。
