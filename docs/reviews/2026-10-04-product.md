# Product review: ordinary tasks, observable results

Reviewed 2026-10-04 against `AGENTS.md`, `docs/requirements-status.md`, `docs/plugin-architecture.md` and the current implementation. This is a source review, with one in-memory synthetic spreadsheet probe. It is **not** a new browser acceptance receipt. The denied browser origin was not visited and no permissions were changed.

The strongest near-term distinction is continuity: a person can express a need, see what actually happened, correct it, and return later without understanding the harness. Extensible interfaces support this when they make a real task easier. They do not compensate for an incorrect appointment time, a misleading total, or an unnoticed failed watcher.

## 1. Bind relative dates to the person, not the execution machine

- **Scenario:** A Shanghai user asks the hosted assistant, “明早八点提醒我去工地”; a traveller asks for “Friday morning” flights while using a server in another region.
- **Evidence:** `backend/athena/skills/tasks/SKILL.md:8` recommends querying the execution machine's local time/timezone. `backend/athena/tools.py:241` reports UTC and `:257` validates only that a supplied deadline has an offset. No client IANA timezone propagation was found in `src` or the backend. Rendering a deadline in browser local time (`src/App.tsx:766`) happens after scheduling and cannot correct a wrong interpretation.
- **Friction:** The scheduler can execute precisely at the wrong human time. A server's timezone and the user's app language do not identify the intended zone.
- **Smallest repair:** Capture the current client IANA timezone as request context outside the stable prefix; persist the chosen zone with a scheduled task and return a human-readable absolute date/time receipt. An explicit user location/timezone wins. When no reliable zone is available, ask once rather than infer from the server. Define civil-time recurrence separately before promising “every morning”; a fixed 86,400-second interval is not that contract across daylight-saving changes.
- **Acceptance:** Fixed clock; Shanghai client against UTC server; “tomorrow at 08:00” stores the correct UTC instant and displays Shanghai's date. Test explicit Tokyo time, midnight boundaries, travel after creation, and a daylight-saving transition. Merely including an offset does not pass.
- **Do not do:** IP geolocation, timezone guessing from language, or expanding the permanent system prompt.

## 2. Make an unfulfilled background promise discoverable

- **Scenario:** “材料价格低于 100 元时告诉我,” followed by a different chat for a trip. The price checker later stops parsing its source or loses access.
- **Evidence:** `backend/athena/engine.py:472-513` persists failed checks and reschedules them; no run is enqueued until a match. `backend/athena/activity.py:32-66` projects runs, not scheduled tasks/check failures. `src/App.tsx:766` displays tasks only in the current conversation; `runtime tasks` is also session-scoped (`backend/athena/tools.py:266`).
- **Friction:** The user can see ordinary completed work across chats, but a still-promised watcher can fail repeatedly without appearing in that account-wide attention surface. Returning to its original chat exposes only a generic retry state.
- **Smallest repair:** Extend the existing activity contract with scheduled promises and a durable attention state for repeated check failures; expose the same list/read/pause operation to Athena. Show the last successful check, next attempt and execution location in detail. Emit one new attention event when a healthy watcher degrades, then suppress identical failures until recovery or a meaningful change.
- **Acceptance:** Create a synthetic watcher in chat A, move to B, induce repeated failures, and verify one discoverable problem with an exact task identity. After repair, verify recovery and one eventual wake. Forked paused tasks must stay paused. Reload and stale acknowledgements must not erase a later failure.
- **Do not do:** Model polling, an always-visible dashboard, noisy per-check notifications, or claiming OS push delivery before it exists.

## 3. Preserve meaning in spreadsheet previews

- **Scenario:** A tradesperson uploads a material estimate with delivery dates, 8% waste and currency amounts, then asks Athena to check the totals.
- **Evidence:** `backend/athena/files.py:261-323` reads cell values without `styles.xml`/number formats; `src/FilePreview.tsx:67-77` displays those strings as the sheet. An in-memory synthetic XLSX probe returned a formatted date as `46299`, 8% as `0.08`, and an amount as `1234.5`, with `truncated: false`. The probe changed no user file or database.
- **Friction:** A readable-looking table can misrepresent the meaning of ordinary spreadsheet values. Formula cache freshness is also not established by displaying a value.
- **Smallest repair:** Preserve raw values and add bounded display formatting for common date/time, percentage, decimal and currency formats; report unsupported formatting and formula/cache limitations in the preview. Keep exported/downloaded originals unchanged. Give the agent the same preview limitations so a “ready” receipt does not imply a recalculated workbook.
- **Acceptance:** Synthetic 1900/1904 date workbooks, 8%, currency, negative numbers, cached and uncached formulas, custom format fallback, malicious/oversized archives. Assert displayed values and unchanged source bytes; do not only assert that a table opened.
- **Do not do:** Build a spreadsheet calculation engine or silently treat stale cached totals as newly computed results.

## 4. Separate conversational interruption from task cancellation

- **Scenario:** While Athena checks flights or edits a budget, a nearby television speaks, or the user makes a short acknowledgement during spoken output.
- **Evidence:** `src/voice-core.ts:8-18` treats 160 ms of sufficient energy as speech onset. `src/voice-session.ts:108-116` cancels playback and invokes the task interruption callback immediately, before recognition. `docs/voice.md` accurately calls this an initial energy detector, not validated full-duplex speech handling.
- **Friction:** Acoustic noise can stop useful work before the system knows the user intended an interruption. Audio-provider success and low unit cost do not establish a comfortable phone-call experience.
- **Smallest repair:** Introduce an explicit candidate-speech stage: promptly duck/pause playback, but do not irreversibly cancel an active tool task on raw energy alone. Confirm speech/turn intent with a local learned VAD and bounded recognition evidence; preserve an explicit stop path. Decide separately whether “嗯/好” should continue listening or supersede the task.
- **Acceptance:** A deterministic recorded fixture containing silence, a short impact sound, background speech, acknowledgement, and clear correction; count unintended task cancellations, missing turns, duplicated submissions and time to stop playback. Then test actual Mac speakers and iPhone microphone, including hang-up and backgrounding. Report synthetic and acoustic evidence separately.
- **Do not do:** Add a second conversation history, auto-replay interrupted effects, or advertise native full-duplex before device acceptance.

## 5. Explain where work and files live at the moment it matters

- **Scenario:** A person prepares a budget on Mac, opens the same account on their phone, and asks “把刚才那个表发给我”; alternatively, a web flight search needs a signed-in browser.
- **Evidence:** `backend/athena/cloud_client.py:38-52` establishes shared identity; sessions/files remain in the local store. `docs/requirements-status.md` explicitly states that Mac sessions/files are separate from the cloud node. `backend/athena/skills/browser/SKILL.md` correctly distinguishes the execution node and reports that cloud browsing has no headed login handoff. The ordinary history/account UI does not explain those boundaries.
- **Friction:** The same account presents an expectation of the same assistant, while chats, files and website login state differ. A nontechnical person may read this as lost work or repeated inability, not a deliberate architecture choice.
- **Smallest repair:** Expose a stable execution/data-location capability through runtime discovery and a quiet account/history detail. In missing-file/session and login-required responses, distinguish “not on this device” from “not found anywhere.” Offer only supported next actions: upload/export or switch to the Mac instance. Preserve the user's draft during any handoff. Cross-node synchronization can be a separate milestone.
- **Acceptance:** Two disposable nodes using one identity: create a file on one, query the other, and verify a truthful limitation plus a working export/upload route; no false claim that the file does not exist globally. A cloud browser login challenge must not create an impossible waiting request for a nonexistent window.
- **Do not do:** Hide implementation limits behind generic errors, copy personal browser profiles, or claim cross-device synchronization from shared authentication alone.

## Suggested order

Start with time correctness and background-promise visibility, then spreadsheet meaning and voice interruption. These fixes have observable daily-task outcomes and reuse the existing runtime/receipt architecture. The execution-location explanation can ship incrementally while synchronization remains a separately tested capability. Avoid enlarging the default shell or undertaking a general service-graph rewrite as a prerequisite for these usability fixes.
